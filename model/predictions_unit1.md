# Unit_1 (traversal unit rate against step latency, one SM at saturation): predictions, written 2026-11-17 BEFORE any run (tethys GPU 1, RTX 4090)

Question: at saturation, what does one more node, leaf slot or triangle cost in RATE (cycles per ray per SM, steady), and is it the one step latency of F67 divided by a constant in flight capacity? Plus a first look at misses in flight when the BVH no longer fits the node state.

Setup (nothing new in the TTU sequence): the checked remap build (--clock --sync --remap --compact-out --regs 64, check_seq ALL PASS, the one Throughput_1 uses), ONE block, 32 warps (and 1 warp for latency), every lane the same ray (+z through x = y = 0, hits nothing), scenes par:N:s (triangles stacked along z) and par:N:o (all overlapping): same N and same triangles, different node and leaf slot counts entered. Counts per ray from the CPU replay of each OptiX built GAS (one ray, box matching exact here because every box holds the ray): nodes / leaf slots / triangles s: N 1: 1/1/1, 4: 1/4/4, 16: 1/12/16, 64: 3/33/64, 256: 9/100/256, 1024: 33/356/1024, 4096: 140/1399/4096; o: 16: 1/6/16, 64: 7/38/64, 256: 27/152/256, 1024: 108/603/1024 (GAS bytes 2.3 KB to 269 KB; 70 KB at N 1024, 269 KB at 4096 beyond the 130 KB node state of the TPC, F150).
Measured per scene: steady cycles per ray c = (median gap between warp ends in the upper half of a 32 warp launch) / 32 (as Throughput_1; the launch span rate is reported too), launches 2..30 (first dropped), and the one warp latency L1 (30 launches, median).
Calibration points already measured (no refit afterwards): c(tri1) = 7.0 (gap 224 / 32 at 32 warps, F176 run); c(par:256:s) = 202 cycles per ray (Throughput_8 solo, 0.00496 rays per cycle at 20 warps, notes/tethys thr8.txt).

Hypotheses (c in cycles per ray per SM, steady):
- H_L (Little, step latencies): c = 7 + (343 nodes + 113 leaf slots + 52 triangles) / 142. The 142 is fixed by the calibration point par:256:s (it equals "about 160 lanes in service" of F90 within the scatter), so only the SHAPE is tested. F67 step costs 343 / 113 / 52 are the L1 cold latencies.
- H_T (triangle rate): c = 7 + 0.76 triangles (same calibration point): nodes and slots free.
Predicted values (cycles per ray): par:1:s 11 | 8, 4:s 14 | 10, 16:s 25 | 19, 64:s 64 | 56, 256:s 202 | 202 (calibration), 1024:s 745 | 785, 4096:s 2958 | 3120, 16:o 20 | 19, 64:o 78 | 56, 256:o 287 | 202, 1024:o 1123 | 785 (H_L | H_T).
The scenes that separate them are the o scenes (same triangles, 1.4 to 3.3 times the nodes and 1.5 to 1.7 times the slots of s at the same N).

Predictions:
1. L1 warm scenes (N up to 1024): H_L within 25 percent on all 10 scenes (p = 0.40); H_T within 25 percent on all (p = 0.15); neither (p = 0.45; then the per element rates from the fit, rule below, say which element dominates).
2. c(par:256:o) / c(par:256:s) between 1.2 and 1.6 (H_L 1.42, H_T 1.0): p = 0.55. c(par:1024:o) / c(par:1024:s) between 1.2 and 1.6: p = 0.55.
3. Least squares c = a + b nodes + s slots + t triangles over the 10 L1 warm scenes (N up to 1024): the intercept a between 3 and 12 cycles (p = 0.6); the ratios b : s : t within a factor 2 of 343 : 113 : 52 (p = 0.4). The triangle cost per triangle lies between 0.15 and 0.8 cycles (p = 0.6), the slot cost between 0.4 and 2.5 (p = 0.6). Collinearity warning: nodes, slots and triangles grow together; the s and o families are what makes the fit resolvable, the intervals of the fit are reported.
4. 1 warp latency L1 within 15 percent of the F67 line (934 + 343 nodes + 113 slots + 52 triangles, L1 cold) for the s scenes up to N 256 (p = 0.5); the warm and cold difference is not predicted.
5. 32 warps against 1 warp: c(N) x 32 lanes ... the ratio of one warp latency to 32 warp steady cycles per warp (L1 / (32 c)) is between 100 and 250 for every scene N >= 16 (the constant in flight capacity, p = 0.45).
6. Misses in flight, first look: par:4096:s (269 KB, beyond the 130 KB node state, L2 warm): c within 15 percent of the H_L value 2958 (p = 0.45: coherent lanes merge their misses, the stream is one node at a time); more than 15 percent above (memory bound, p = 0.45); more than 15 percent below (p = 0.10). If above: M_est = (GAS lines per ray x 285 cycles L2 latency) / c, with 2,100 lines per ray, is reported as a lower bound of the misses in flight the unit sustains per SM, no more.
Reading rules: (a) "H_L holds" needs prediction 1 as stated; (b) if H_T-like (o scenes within 10 percent of s at the same N), triangle count alone sets the rate and the slot and node latency steps are hidden; (c) the fit is the answer in the other cases; no refit of the model constants from this run (F67 constants stay), new rate constants would be added next to them with their intervals.
Safety (all as before): stage 0 first on the largest layout, smallest TTU launch first (1 warp, 1 launch, tri1 scene), every run under run.py (timeout -k 2 30, checked binary, idle GPU 1), stop at the first fault, hang, wrong result or missing block (nothing retried), one TTUOPEN / macro fuse 17 / one close per sequence (the same checked bytes as Throughput_1), raw JSON per run with a timestamp name, never overwritten.
