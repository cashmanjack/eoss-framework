## Item 3. TrueKNN at K 50 and 128: a bound
Why F249 had none: a stub callback that returns at once never decrements numNeighbors, so every query stays active forever and the rounds never end. Bound by replay: the original (Vani's program, F245 build, src_scope plus a recorder) writes each round's active mask (numNeighbors > 0 at the start of the round, one byte per query, device side write in raygen, copied after the launch outside the timers). A stub build (intersection program returns at once, same traversal, same program invocations, same radii and the same doubling, same refit) replays those masks: raygen reads the mask array instead of the frame buffer, so no managed memory migration and no K x 24 byte records are touched. Its device scope (build + launches + refits) is a lower bound for any fix of the callback body, because OptiX does the same box tests and program calls (the program never reports an intersection, so tmax never shrinks). It excludes fixes that avoid invoking the program or change the number of rounds. The stub is slightly cheaper than the original in raygen (a coalesced byte read instead of one strided load): that only makes the bound lower, which is the safe side. Cells: 8 datasets (3DRoad, Porto 1M, uniform 1M, bunny, dragon, Gowalla, Glove 3D, Manuscript) x K 50, 128 = 16 cells, same start radii and arguments as F245/fair_run.py. Per cell: 1 recorder run of the original (also gives the paired original time), 3 stub runs. Hubs, RTNN and F245 TrueKNN times as in model/priorworks/results_fair_table.md.
- T1: the stub replays the original's rounds exactly (same number of rounds, same radii, same active counts per round) and runs without fault in all 16 cells: 85 percent. If a cell cannot run (memory, time) it is listed with the reason.
- T2: stub device scope is below the original's in all 16 cells: 90 percent. Median stub / original: 0.10 at K 50 (range 0.03 to 0.35), 0.04 at K 128 (range 0.01 to 0.15): 55 percent for the medians being inside these ranges.
- T3: number of cells where stub < hubs: K 50 between 2 and 5 of 8 (60 percent); K 128 between 0 and 2 of 8 (70 percent).
- T4: cells where stub > hubs (so no callback only fix can bring TrueKNN to hubs): between 11 and 15 of 16: 60 percent.
- T5: stub is still slower than RTNN in at least 12 of 16 cells: 70 percent.
Rule to close the open item: a number per cell (stub, original, hubs) and one sentence per K: which cells a callback only fix could win and which it cannot. If the replay cannot be made exact, say why no bound is possible and close with that statement.
