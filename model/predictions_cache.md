# Cache_1 / Cache_2: predictions, written 2026-11-17 BEFORE the measurement runs (tethys GPU 1, RTX 4090, plain CUDA, no TTU)

Program ttu/bench/Cache_1/cache1.cu: one thread of one block follows a dependent chain of m addresses at a byte stride S (sequential cyclic or random cyclic order), average cycles per load by clock64, loads .ca (through L1) or .cg (L1 bypass, L2). Hit latencies known: L1 41, L2 285 (F176), DRAM about 620 to 650. "Miss fraction" = (latency - 41) / (285 - 41) for L1 tests. A knee = the first point where the latency passes the midpoint of the two levels. Modes: l1cap, l1sect, l1assoc, l1repl, l2assoc, l2lat.
DISCLOSURE: one smoke test of the program (l1sect, to see that it runs) was run before this file was committed: sequential order, 1 MB array: stride 4 / 8 / 16 / 32 cycles 70 / 101 / 163 / 285, random order 279 to 285 at every stride. It shows the 32 byte sector (miss fraction = stride / 32 up to 32); the prediction below for the sector was written before looking at it as 32 bytes (the number is the NVIDIA documented one, so it was not a blind measurement).
Predictions:
1. L1 sector 32 bytes (held by the smoke test: miss fraction 0.125 / 0.5 / 1.0 at stride 4 / 16 / 32). L2 sector 32 bytes (not tested directly).
2. L1 capacity (l1cap, stride 128, sequential cyclic, no shared memory in use): knee between 96 and 128 KB, p = 0.6 (F150's plain probe saw 80 to 96 KB on the 6000 Ada; Ada has 128 KB of L1 plus shared memory per SM). Sharp (LRU like) for sequential order: latency goes from 41 to 285 within 8 KB; random order: gradual.
3. L1 tag line 128 bytes: the capacity knee at stride 32 and at stride 64 is at the same footprint N (within 10 percent) as at stride 128, p = 0.7 (a 32 byte tag line would put the stride 128 knee at 4 times the footprint). At stride 256 the knee is at 0.9 to 1.0 of that footprint, i.e. no loss to set conflicts, p = 0.45 (a modulo set index would halve it).
4. L1 associativity (l1assoc): for strides S >= 16 KB the latency rises from 41 at a number of ways m* that does not change with S: m* = 4 p = 0.3, 8 p = 0.2, 16 p = 0.15, 32 or more p = 0.1, no clean value (hashed set index) p = 0.25. A clean plateau value exists p = 0.6.
5. L1 replacement (l1repl, m = ways + 1, sequential cyclic): miss fraction at least 0.9 (LRU like, the cyclic worst case), p = 0.5; between 0.3 and 0.9 (pseudo LRU or random) p = 0.4; under 0.3 p = 0.1.
6. L2 per line hit latency over 16 MB (l2lat, warm, .cg, random order, one SM): a single mode, 95 percent of the lines within 15 percent of the median, p = 0.65 (a near and far partition would show two modes more than 10 percent apart; the 4090's L2 is 72 MB in one piece as far as published).
7. L2 associativity (l2assoc, .cg, strides 4 KB to 2 MB, m up to 160): no knee below the cache size at any stride (the set index is hashed across slices), p = 0.5; if a knee exists at large strides it is at 16, 24 or 32 ways, p = 0.4 (given a knee).
8. Node state (the TTU's own node lines): NOT measured here (plain loads cannot create node state lines, F147); line and associativity of the node state stay open in the matrix.
Reading rules: a prediction holds if its stated range or value matches; for 4 the value must repeat at three strides within one way; for 7 the plateau counts only if it repeats at three strides. Safety: no TTU instruction; GPU 1 idle (0 percent, no process) before each mode; timeout 600; raw text with timestamp names never overwritten. Time cap one day.
