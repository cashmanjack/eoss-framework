# Queue 17: mean value analysis (closed queueing network) for the loaded callback latency. Form fixed 2026-11-16 before the run. CPU only.
Question: can the loaded latency per warp call (F133: 1.3 to 16 times the unloaded one) be predicted from unloaded costs and warp counts alone?
Network (one customer class, one SM; customers = warps in flight W from ncu, non integer W by linear interpolation between the neighbouring integers):
- Queueing station ISSUE: demand f = floor cycles per warp call (F131: instruction counts x microbenchmarked costs, = T_floor x SMs / calls).
- Variant V1: everything else a delay (infinite server): Z = C_unl - f, with C_unl = summed warp cycles per callback call in the one warp per SM launch (1,920 queries, 60 warps). So memory, traversal unit, L2, DRAM and the 875 cycle hand off (F137) are delays and only the issue queue contends.
- Variant V2: the non issue part of the callback, Lm = L_unl - f, is one FIFO server per SM (L1 / LSU / L2 port as a single resource, all of the unloaded memory time is service); Z = C_unl - L_unl is a delay (traversal unit, hand off, raygen). This is an upper bound on contention.
- Not separable with the data at hand (no per call request counts for kNN, Arkade): the split of Lm into L1, L2, DRAM service; the per TPC traversal unit demand (two SMs share one unit; customers there would be 2W) and a hand off station. They are left inside the delays, and the report says what a separation would need.
Output per workload: predicted loaded latency per call = (queue residence at W) + (delay part belonging to the callback, L_unl - f for V1; 0 more for V2, whose server residence is the whole callback). Exact MVA: R(n) = D (1 + Q(n-1)), X(n) = n / (R(n) + Z), Q(n) = X(n) R(n).
Compared with: measured loaded latency (F133), the unloaded latency (no contention), and the post hoc rule of F133 (L = L_unl + (W-1) k f, k = 0.37 from RTNN). Error = log(predicted / measured), rms over workloads of a kind.
Prediction written now: V1 fits RTNN sorted and RT-BarnesHut (throughput like callbacks, error under 0.2) and under predicts kNN and Arkade by a factor 3 or more (their cost is a chain of dependent memory round trips that queue in the memory system, not at issue). V2 over predicts everywhere except kNN and Arkade, where it lands within a factor 2. If so, no single network without a per call memory request count separates them.
