# Energy per RT query, first test (RTX 4070 Ti, io, GPU 0, 2026-11-13)
NVML total energy counter (nvmlDeviceGetTotalEnergyConsumption, millijoules): works on the 4070 Ti. It agrees with the power draw (a busy loop read 92 to 125 W, idle GPU 1 read 7 W and 14.6 J in 2 s), and it updates every 100 ms (16 updates in 1.5 s), so a window of 3 s has up to about 3% granularity error; this matches the 1 to 2.7% run to run spread seen.

Method (code: ttu/bench/Energy/energy_run.py, host option --energy S in ttu/harness/setup3/setup3.cu): the checked launches first, then the same launch repeated back to back for 3 s (read flush kernel of 96 MB = 2 x L2 before each launch for the DRAM state), counter read before and after, SM and memory clock sampled (SM 2865 to 2880 MHz in every kept run, memory 10,251 MHz; the first run of each group started at 2230 to 2470 MHz and is discarded as a warm up), 3 repetitions per state, median. One block per SM on all 60 SMs, 1 warp (32 queries per SM per launch) or 16 warps. Each state is the difference to the same build without TTU instructions (stage 0), which carries the loads, stores, clock reads and launch: L2 = single query, no flush (L1 empty at kernel start, BVH in L2); DRAM = single query after the flush; L1 = second query in the same kernel (twice build) minus single, minus the same difference in stage 0. Idle power measured with nothing running before and after each group: 17 to 25 W (drifts with temperature and power state).

Result: per query energy above the no TTU harness (microjoules per query, 3 repetitions, the noise is about 0.01 for 16 warps, 0.03 to 0.25 for 1 warp):

| scene (depth) | warps | L1 (2nd query) | L2 | DRAM |
|---|---|---|---|---|
| 1 triangle | 1 / 16 | -0.004 / 0.003 | 0.022 / 0.006 | -0.24 / 0.015 |
| grid 144 | 1 / 16 | 0.009 / 0.003 | 0.016 / 0.002 | 0.060 / -0.007 |
| grid 2,500 | 1 / 16 | 0.003 / -0.004 | 0.021 / 0.005 | 0.21 / 0.005 |
| grid 20,736 | 1 / 16 | -0.002 / 0.004 | 0.024 / 0.005 | 0.14 / 0.005 |

Reading, honestly: this harness cannot resolve the energy of a query. The whole launch is 0.52 to 0.58 mJ (1 warp) or 7.8 to 8.0 mJ (16 warps), 60 SMs, about 95 to 119 W; the version without TTU instructions is already 97 to 98% of it (0.19 to 0.21 microjoules per query above idle, the cost of the harness's loads, stores and clock reads), and a query adds 0.5 to 3% (2 to 24 nanojoules), as big as the noise. The one number that is above noise, the L2 state with 1 warp (about 0.02 microjoules, same for every depth), is as large as the extra latency times the card's power (the traversal adds about 0.6 microseconds to a launch at about 95 W = 0.06 mJ per launch, about 0.03 microjoules per query), so it says "waiting costs static power", not "a node fetch costs x". The DRAM state with 1 warp (0.06 to 0.21 microjoules, one value negative) is inside the 2% noise of a 27 mJ launch dominated by the flush. No depth, no level difference can be claimed. What would work: a persistent kernel where RT work is most of the energy (Throughput_6L style, millions of queries per launch), counter window 10 s or more, power above idle divided by the query rate, and the energy of the flush measured on its own with a long enough window; not done.
