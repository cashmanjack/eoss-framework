# Mask_1 results (2026-11-17, tethys GPU 1; predictions model/predictions_mask_ias.md, committed first)

Code reading (dumped traversal code, base and mask 0 windows, notes/flagenc, private): the ray mask byte is used for (a) the store words (top byte of word 0, bits 23:16 of word 2) and (b) three tests "mask byte non zero" that guard the call into the traversal body together with a non null handle test. No instruction ANDs it with an instance mask in software, so for non zero masks the unit does the AND. For mask 0 OptiX skips the traversal body in software and returns a miss without any TTU instruction (this explains mask 0 hit in our Flags_2 sequence: it has no such test, and the unit did not reject the zero mask against the identity instance of a single GAS pipeline). The branch polarity is read from the control flow (the call only makes sense for a non zero mask), the decoder drops the predicate lookup table; not run on the GPU in isolation.
OptiX only (Flags_1 ias:1:D imask=15): instance mask 0x0F, ray masks 0xF0 miss, 0x01 hit, 0x10 miss, 0x0F hit, 0xFF hit, 0x00 miss; instance 0xFF: ray 0x00 miss, 0x0F hit. All 262,144 rays hit or miss together (hit fraction 0 or 1). Predictions 1 to 4 held.
Our sequence: the IAS group (17 instructions, its own stores; store 0 and 0x80 mask words computed by ias_words.py, same positions as the GAS group, word 1 0x5a455408 / 0x5a450408 instead of 0x5a400408) is prepared for ray masks 0xF0, 0x01, 0x10, 0x0F, 0xFF, 0x00 (setup3 --ias --imask 15, /dev/shm/t9i, check_seq ALL PASS on all 12 builds, stage 0 ran clean). NOT RUN at stage 1: an IAS stage 1 sequence has never run on a GPU (F91, F114 only ran stage 0), so more than store words differ from Flags_2. Needs Jack's approval.
