Real test: measured DRAM bytes per launch.
Run: the same 8,388,608 random rays (seed 2026) and the same 7 orders as F205 (ttu/bench/Morton/dram_orders.py rebuilds them without the replay: 59.4 percent hits, 6,704,264 triangles and a 416.3 MiB GAS, equal to F205), ncu on the Morton host, only the second optixLaunch of each order (the first is the host's untimed warm up; the benchmark times 10 launches after it, so L2 starts warm with the same order), --cache-control none, --clock-control none, TMPDIR a directory we own (F179). One launch per order (ncu), so noise is not measured; the ncu duration is compared with the F205 median ms as a sanity check (ncu serialises and adds overhead, so 10 to 40 percent above is expected).
Feature to compare: F209 D bytes per launch = D (B per ray, notes/hs/predict_rungholt.json) x 8,388,608: natural 2.12 GB, d1 1.51, d2 1.30, d3 1.21, d4 0.96, full 0.58, Morton 1.22 GB.
