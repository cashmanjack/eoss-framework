What the hits mean: the TTUCCTL behaves the same with a performance monitor predicate, any of four scheduling pairs tried, or a wait that is already satisfied: no field of that instruction except the predicate and the write scoreboard changed anything (F435 and here). A standalone TTUMACROFUSE 0 is harmless and does not invalidate. TTUST's read scoreboard index is not tied to index 0. The 0xC0 store is not a harmless duplicate of 0x40 on a hit: without it the ray hit is lost, and a miss ray session gets shorter (the unit does less); that fits the store map in notes/protocol.md only if 0xC0 and 0xD0 carry the ray the unit uses first, which is not tested here. The non dual open does not run the traversal of this fuse 17 group: it returns at once with no hit.
