Result registers: in both new forms every result register equals its input value except one word, 0xE0000011, in the same register as in the F440 non dual run, and the address like words; no t, u, v, prim or hit flag is delivered. So the loads execute and return an "empty" answer. The session length does not depend on the scene (486 on both scenes, 527 on both): there is no traversal. Length grows with the number of TTU slots: 486 for 8, 527 for 10 (20.5 cycles per slot), and 17 slots at that rate gives about 670 against the 689 of F440: about 320 cycles fixed plus about 20 per slot.
Scoring: predictions held (ces1 no hit and short, 0.6; ces2 no hit and short, 0.55; no hang, no fault). Not predicted: the identical status word and the linear length.
What DUAL changes (as far as these data go): with the DUAL bit the fuse 17 group traverses (1,594 cycles on a hit); without it the session returns an empty answer after about 320 plus 20 per slot cycles with three different store sets (the 17 slot OptiX set, Cesar's 4 stores, Cesar's plus 0xC0 and 0xD0), so the store set is not what makes the non dual session fail here. What is NOT shown: whether a non dual open traverses with some other store set or none of ours; whether the DUAL bit alone with Cesar's set traverses (a control of ces1 or ces2 with DUAL set was not built: not approved). The hypothesis that DUAL turns on the instance level path (stores 0x100, 0x180, 0x190 and the root) is not tested.
